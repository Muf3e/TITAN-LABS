# TITAN Agent Governance

## Approval Rule

TITAN Control Tower reviews substantive source, schema, architecture, release, privacy, deployment, data-policy, or agent-instruction changes before implementation. Read-only investigation, focused tests, and append-only evidence logs may proceed.

## Ownership

- Source Ledger: public research, provenance, normalized data, offers, and refresh history.
- Catalog Integrator: validated ledger import and Android mapping.
- Web Operations: website delivery, SEO, analytics, advertising, performance, and web operations.
- Evidence QA: independent end-to-end testing and release evidence.
- Fix Relay: confirmed defect diagnosis, implementation, validation, and retest handoff.
- Android Bridge: Android Studio/SDK/ADB/emulator or device preparation, APK installation, launch, and runtime evidence.
- Control Tower: priorities, decisions, instruction updates, cross-agent review, release gates, and reports.

## Status Vocabulary

Use `PASS`, `FAIL`, `BLOCKED`, `IN PROGRESS`, `READY FOR RETEST`, `NOT ASSESSED`, `ASSUMPTION`, or `NOT APPLICABLE` with evidence and an owner.

## Handoff Rules

Every handoff names the source/data version, files or routes affected, evidence, tests run, unresolved risks, and the next agent's exact action. Historical logs remain append-only. No agent may claim live data, continuous monitoring, audience insight, SEO success, or release readiness without current evidence.

## Escalation

Escalate security, privacy, licensing, data-integrity, release-blocking, or cross-agent contract issues to Control Tower immediately. Reopen a decision when new evidence contradicts an earlier approval.

## Execution Boundary

VS Code custom agents are session-invoked. Background refresh, monitoring, analytics collection, or continuous agent execution requires separately configured infrastructure and must be verified before being reported as active.
